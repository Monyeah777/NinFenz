## 背景

ADR-0004（2026-09-26，accepted）确立抽象阶梯「两轴 + 纵切」，并在「后果」中明确划定代价：
阶归属判据**有界**——只判阶梯自己声明的真源面，**不给全树逐文件贴标签（那属另一个量级的承诺）**。

2026-10-14 在 HEAD 上实测，该「有界」的边界已经不够用：

- 提交树共 **1648** 件；其中 `desktop/src/core/*.py` **242** 件、`desktop/tests/**` 329 件、
  `engine/**` 394 件（第二实现线已大于核本身）。
- **阶梯轴对核内零分辨力**：按 `protocol/LAYERS.json` 各阶真源面展开，242 件 core 模块**全部**落在「引擎」一阶。
  即「它属于哪一阶」回答不了「它在工坊里干什么」。
- 而跨核法（跨核只走地板 / 核有尺寸上界 / 投影收敛为一条通道）**必须按件知道它属于哪一核**才能判定；
  缺逐件坐标时，这三条法则都只能是口号。

## 决策

1. 增设**职能坐标**作为与阶梯轴**正交**的第二轴，取值封闭集：
   `floor`（身份/寻址/注册）、`prod`（件·装配律·派生）、`verify`（声明·见证·判据）、
   `projection`（真源→渲染→落点）、`support`（基础设施）、`app`（实例与内容）、`entry`（入口面）。
2. **核内逐件，核外按规则**：`floor + prod + verify` 三面的每一件必须给出职能坐标 + 一句职能句，
   且职能句须**可从证据推导**（模块自述、注册表登记、写通道、消费者），不得手填即算；
   `app / projection / support / entry` 由**登记在册的 glob 规则**覆盖，规则可检、可驳、可删。
3. **三条可判定性**并入既有判据，**不新增 check 序号**（遵 ADR-0002）；形状类断言按 ADR-0003 进
   `protocol/assertions.json`：
   ① **全覆盖**：每个 tracked 件至少命中一个坐标，未归类数恒为 0；
   ② **规则不漂**：每条 glob 至少命中 1 件，命中集互斥或显式声明重叠；
   ③ **核内一致**：声明为只读判据的件不得出现在写通道（`--write/--refresh/--freeze`）里。
4. 本 ADR **取代 ADR-0004 的「不逐件贴标签」条款**；ADR-0004 的两轴阶梯本体（四阶·入口面·纵切·不新增 L 编号）
   继续有效，交由本 ADR 承接其边界条款。

## 后果

- **好处**：跨核法与核尺寸上界第一次**可判定**；「核有多大、成本压在哪」从感觉变成可数事实；
  `engine/**` 大于核本身、`desktop/src/core` 242 件这类事实第一次进入判据面。
- **代价**：核内逐件维护（首次推导实测 242 件 core：verify 113 / support 24 / prod 16 / projection 7 /
  floor 3 / **待裁定 79**）；核外规则集本身成为维护对象，用②兜住其腐烂。
- **上界纪律**：核外不逐件；新增判据不涨 check 号；「待裁定」必须逐件裁，**不得以「覆盖率 100%」掩盖**。
- **遗留**：首次推导的 79 件「待裁定」是本次决策的**直接工作项**，不是数据噪声；
  其中相当比例的自述为「机制借鉴 X」——即核的增长方式是「每补一类能力吸收一条外部机制」，
  该增长方式本身需要与 STRATEGY §3.2/§3.4 的「外部输入已吸收完毕、无需持续外求」对齐复核。
