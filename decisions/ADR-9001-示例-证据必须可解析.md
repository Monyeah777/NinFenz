## 背景

`evidence` 是决策的**可证链条**：写不可解析的条目等于没有证据。

证据链断掉的后果是具体的：一次 `nf decisions verify` 红掉整条链；更糟的是「看起来有证据」的决策
在复核时无法逐条落地——门禁因此可被绕过（评审只能看正文，看不了支撑）。

## 决策

`evidence` 只允许三类，且每项必须能**当场解析**：

1. 仓库内可解析的**相对路径**（指向文件，不是目录）；
2. `checkN` 形式的判据编号（须在 `verify.sh` 在册）；
3. 在册**ADR id**（如 `ADR-0000`，解析到 `decisions/` 内对应件）。

禁止项（由 `nf decisions` 逐条判 FAIL）：绝对路径（含盘符）、`..` 路径穿越、目录、空项、
单项超过 512 字符（`MAX_EVIDENCE_LEN`）、引用不在册的 ADR id。标量写法（不加方括号）按单项解析，
不会按字符拆开。

> 本示例自身的证据指向：ADR-0000（机制决策本体）+ `desktop/tests/test_decisions.py`（逐条校验用例）
> + check33（新面汇总的决策层面门禁）——三者共同证明「证据可解析」不是口头约定。

## 后果

好处：`nf decisions verify` 能逐条核验；证据链可被评审与门禁同时消费。
代价：私有档案中的决策若引用内部件，先在本仓放置等价可达件或改指向 `checkN`。

可核验面（判据落点）：

- 解析与边界：`desktop/src/core/decisions.py`（`MAX_EVIDENCE_LEN = 512`、绝对路径/穿越/目录/空项/不在册 ADR 逐条诊断）；
- 行为用例：`desktop/tests/test_decisions.py::TestEvidenceBoundaries`（六种边界各一例）；
- 门禁：check33 新面汇总门禁（决策层面）与 `nf decisions verify`；
- 勘误通道：证据指针写错走 `decisions/ERRATA.json` 登记（只改引用指针，不改 ADR 正文，回执锚定不失效）。

## 证据写法（示例）

| 写法 | 判定 | 原因 |
| --- | --- | --- |
| `evidence: [decisions/ADR-0000-决策记录外置到私有仓.md, check33]` | ✅ | 相对路径 + 在册 checkN |
| `evidence: [ADR-0000, check33]` | ✅ | 在册 ADR id + 在册 checkN |
| `evidence: [/etc/passwd]` | ❌ | 绝对路径 |
| `evidence: [../outside.md]` | ❌ | 路径穿越 |
| `evidence: [decisions, check33]` | ❌ | 目录不是证据（`不是文件`） |
| `evidence: [art.md, , check33]` | ❌ | 有空项 |
| `evidence: [ADR-9999]` | ❌ | 不在册 ADR id |
