## 背景

（写清**为什么现在必须做这个决定**：约束、冲突、不做的代价。）

> 写法：给出现状与触发条件（何时/因何必须决策），不要只写「为了更好」。
> 若本条取代旧决策，在 frontmatter 用 `supersedes` 指向旧 id（被取代件在 `superseded_by` 回指）。

## 决策

（一句话可执行：改什么、不改什么、边界在哪。）

> 写法：首句给可执行结论，必要时编号列条目；写清**不改什么**（边界）与判据落点（哪条 test/check 守住它）。

## 后果

好处：（可观测的收益）
代价：（接受的代价；将来如何被取代）

> 写法：好处要可观测（有判据/门禁承接），代价要具体（可接受 + 恢复路径：新开 ADR 取代，而不是就地删判据）。

## 写法指引（本模板怎么用）

**frontmatter 七键**（`nf decisions` 机读解析；缺键或越词表即 FAIL）：

| 键 | 取值 | 说明 |
| --- | --- | --- |
| `id` | `ADR-9xxx`（模板）/ 真实编号在私有仓 | 与文件名前缀一致 |
| `title` | 一句话标题 | 与 INDEX 投影行一致（勿手改 INDEX） |
| `status` | proposed / accepted / superseded / deprecated | accepted 须已被协议回执锚定 |
| `date` | `YYYY-MM-DD` | 首次登记日期 |
| `supersedes` | 旧 id 或 — | 取代链由工具校验（闭环 + 单向） |
| `superseded_by` | 新 id 或 — | 与被取代件互指 |
| `evidence` | 仓库相对路径或 `checkN`，逗号分隔 | 逐条可解析；不得绝对路径/目录/超长 |

**三段写法要点**：背景（约束与触发）→ 决策（可执行结论 + 边界 + 判据落点）→ 后果（可观测好处 / 代价 / 取代路径）。

**投影与自动化**：INDEX 由 `nf decisions reindex` 从各 ADR frontmatter 重建，勿手改；勘误只登记引用指针（`ERRATA.json`），不改 ADR 正文（回执锚定不失效）；真实决策请写私有 Plan 仓 `governance/decisions-archive/`，公开仓本目录只保留模板（ADR-0000）。
