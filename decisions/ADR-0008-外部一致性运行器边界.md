## 背景

NF 已有内部一致性报告，但还没有外部 conformance runner。若让运行器只调用 NF 自己的
`--declaration` 再核对自己的声明，验证者与被验证者会共享同一盲点，不能形成外部证据。
另一方面，把“未执行”“输入错误”和“范围未覆盖”混成失败或通过，都会制造不诚实的
一致性叙事。

## 决策

1. **当前不采纳外部 runner。** 只有内部机器报告、标准断言账本和负例证据齐备后，才可另立
   实现工单；在此之前任何输出只能写“外部一致性未执行”。
2. **执行体独立。** 未来的 runner 必须在独立仓库或独立进程实现，不得只调用 NF 的
   `--declaration`、内部报告生成器或其测试夹具来完成自我判定。
3. **范围显式。** 每次运行必须携带标准编号、版本、scope、排除项和断言清单；结论只能覆盖
   清单中实际执行的项，不得外推为整个标准或整个仓库已认证。
4. **退出码单义。** `0` = 显式范围内全部通过；`1` = 范围内断言失败；`2` = 未执行或证据不足；
   `3` = 输入/schema/引用错误；`4` = 运行器基础设施错误。`2` 和 `4` 不得被解释为通过。
   **未执行不等于通过。**
5. **证据可复核。** 输出至少记录 runner 版本与摘要、被测 commit、输入摘要、scope、逐项结果
   和总摘要；运行结果不得写回 NF 的静态基线，只能作为带时间与 commit 的外部证据归档。

## 后果

NF 可以继续使用内部 conformance 报告，但不得把它包装成第三方认证或外部 conformance。
未来 runner 的接入成本会更高，但验证边界、失败语义和证据来源都能被独立复核；如果改变这些
约束，只能新增 ADR 取代本件，不能修改本件历史。
