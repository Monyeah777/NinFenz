# NinFenz 0.3.7 性能基线

> 口径：M-01 OnePlus PLF110 / Android 16；飞行模式、充电、常温；≥10 次、先预热一次；P50/P90；同输入两次方差 >10% 判无效。
> 无设备/无数据写 no-data + owner，禁止手搓。

## 仪表状态

- `:benchmark` 模块已建立，依赖 benchmark-macro-junit4 1.3.4 / uiautomator 2.3.0 已解析。
- `:benchmark:compileBenchmarkKotlin` 通过；`:app:assembleBenchmark` 通过。
- StartupBenchmark / FrameBenchmark / BaselineProfileBenchmark 已编写。
- 2026-11-28 收口（最终形态）：类遮蔽不是「逐类 keep 能补完」的——只要两侧都开 R8，同进程共享类就会逐层被裁（依次命中 kotlin Intrinsics → androidx.arch/startup/tracing → lifecycle 接口）。最终处置：
  1) **benchmark 变体关闭代码/资源压缩**（`isMinifyEnabled=false, isShrinkResources=false`），测试模块同步关闭压缩 → 两侧 APK 保持原始类形态，类遮蔽根除；**生产 release 仍是全量 R8**，发布物不变（口径差异仅影响 benchmark 变体）。
  2) **测试模块启用 `android.experimental.self-instrumenting=true`**——macrobenchmark 要求「自测」：测试 APK 在自己进程运行，再 kill/compile/launch 目标 app；原 `targetProjectPath` 默认形态会被 androidx.benchmark 判 `NOT-SELF-INSTRUMENTING` 拒绝。
  3) benchmark 变体 manifest 声明 READ/WRITE_EXTERNAL_STORAGE（MacrobenchmarkRule 会 grant 给被测包；未声明则 `Failed to grant permissions`）。仅 benchmark 变体，**release 清单无存储权限**。
- 构建：`:app:assembleBenchmark` + `:benchmark:assembleBenchmark` 通过（app-benchmark.apk ≈25.0MB 未压缩、测试 APK ≈38.2MB）。
- **harness 冒烟（headless API 36 x86_64 模拟器）**：instrument 成功启动、目标 app 正常拉起并进入测量阶段（自测进程/权限/类加载全部通过）；在等待 activity launch completion 时，模拟器 `dumpsys gfxinfo framestats` 无法确认帧序列 → `Unable to confirm activity launch completion`（androidx.benchmark 的模拟器限制，非 app 崩溃、非类遮蔽）。结论：**harness 实现面闭环，模拟器不适合作启动完成判定**；正式 P50/P90/jank 仍需真机。
- 设备口径：`adb devices` 无真机（USB 只有 PLF110 充电态、无 ADB 接口）。设备接上后跑 `app/scripts/device_macrobenchmark.sh`；模拟器冒烟可加 `-e androidx.benchmark.suppressErrors EMULATOR`。
