## 2. 阻断（已修复）：minified / Play 包启动崩溃

- 现象：minified 变体（benchmark 变体，与 release 同源）启动 FATAL：
  `RuntimeException: Unable to get provider com.google.mlkit.common.internal.MlKitInitProvider: ClassNotFoundException`（initOrder=99）。
  证据 `0.3.7_device_mlkit_crash_before_fix.png`。
- 根因：D1a 把 MLKit 移到 on-demand `:feature:ocr` 后，AGP 仍把 feature 的 manifest 组件（`MlKitInitProvider`、`MlKitComponentDiscoveryService` + 3 个 Firebase ComponentRegistrar meta-data）合进 base merged manifest（manifest-merger blame 指向 `[:feature:ocr] metadata_feature_manifest`）；而 base dex 里没有 MLKit 类（R8 已裁掉）→ provider 实例化即崩。
  AAB 的 base manifest 同样包含这些组件（`bundletool dump manifest --module=base` 实测），即 Play 安装的 base APK 也会崩，不只是侧载 APK。
- 修复：
  - `app/src/main/AndroidManifest.xml` 对上述 2 个组件加 `tools:node="remove"`（组件由 feature split 安装时自行声明）；
  - `:feature:ocr` 改 `dist:fusing include="false"`（minSdk 26 无需 fused/universal 打包）。
- 验证：
  - release APK / benchmark APK 的合并 manifest `mlkit` 计数 **0**；AAB `base` manifest 计数 **0**。
  - minified 变体冷启动 257/167/177/182/178ms，无崩溃（`0.3.7_device_releasevariant_home.png`）。
  - **Play 形态安装**（bundletool local-testing：base + split_config.arm64_v8a + split_config.xxhdpi，ocr 模块不装）冷启动 193/186/176ms，无崩溃，首页正常（`0.3.7_device_playlike_home.png`）；`pm path` 确认仅 base+2 个 config split。

## 6. 直装融合包真机验证（2026-11-28，发布前最终形态）

- 产物：`nf-mobile-0.3.7-preview.1.apk`（universal，43,533,303 B，SHA-256 `3798bf48…`，upload key `A4:F4:68:7A…`）。
- 安装：`adb install --no-streaming` 成功；前置需 `am force-stop com.oplus.appdetail`（该机 OPLUS 安装校验策略，非 APK 缺陷）。
- 冷启动 `am start -W` TotalTime：172 / 178 / 202 / 205 ms（4 次）。
- 核心链路：示例内容导入成功（JNI/JNA 全部 op 可用）；图片（jpg/png）导入经本机 MLKit OCR 成功产出文本并进入导入预览（1/4 步，结构 1 段）。
- 本次真机验证发现并修复 3 个 release 阻断（均有映射/日志实证）：
  1. JNA keep 规则写成不存在内部类名（`CoreBridgeNative$CoreNativeLib`），R8 把 `CoreNativeLib` 改名并裁掉方法 → `Native.load` 抛 ClassCastException → 所有核心 op 报 NF-E-005。修：keep 真实 FQN（`dev.ninfenz.mobile.core.CoreNativeLib`）。
  2. MLKit `TextRecognizer` 在主线程调用即抛 `Must not be called on the main application thread`，被 OcrFeatureBridge 兜底误报为「OCR 扩展未安装」。修：识别与 PDF 兜底 OCR 走 `Dispatchers.IO`。
  3. 导入「选择文件」MIME 列表不含图片 → OCR 在侧载/直装形态不可达。修：补 image/* 并把 4 处调用收敛为 `ImportMime` 单点常量。
- 数据：验证前已备份设备数据到 `D:/ninfenz-backup/device-20261128/app-data-full.tar`（426,042 B）；验证结束后恢复 debug 构建与数据（见 §5）。
