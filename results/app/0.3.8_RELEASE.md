## 1. 结论

- 版本：`0.3.8-preview.1`（versionCode 11，minSdk 26，targetSdk 36，包名 `dev.ninfenz.mobile`）。

4. **release(R8) 构建真机**（debug 签名同源构建，功能验证后不再改动代码）：

   - 设置页「核心诊断」：backend `jna-native`、ABI `nf-app-core/1`、原生库**已加载**、错误码 **117 条**（证明 R8 后 JNA 与核心可用）；

5. **上传签名产物静态校验**：`apksigner verify --print-certs` 证书为 NF Upload；`zipalign -c -P 16 4` exit 0；universal 内含 MLKit/PDFBox/双 ABI。
6. **门禁**：`PYTHONUTF8=1 bash verify.sh --checks-only` → PASS=107 WARN=2 FAIL=0（WARN 为存量提示，非本次引入）；`nf conformance --write` 27/27 conformant，批准记录重签有效；`receipts --scope protocol --write` 66 件，透明链自洽。

## 6. 环境注意（复现门禁时）

- Windows 上必须设 `PYTHONUTF8=1`（否则 `git ls-files` 文本模式按 GBK 解码，conformance 的 `modeling` 契约会异常）；这不是 0.3.8 引入的问题，是本地 locale 缺陷。
- 核心重编译：`bash app/scripts/build_core_android.sh`（NDK 27，两 ABI，release profile）。
- 产物构建：`./gradlew :app:bundleRelease` → `bundletool build-apks --mode=universal`（upload key 签名）→ `zipalign -c -P 16 4` 校验。
