## 一、目的与定位

外部实测封存后，用**内部仿真**验证「AI 读协议能否执行对」：给每条管线写内部演练回合集，协作 agent 按协议执行并与断言比对——内部演练同构于外部 AI 执行且可复现。**内部演练 ≠ 外部转正**（不混标，docs_external-validation 封存位不变）。

## 二、演练格式（GWT · NF 化）

每个演练样本 = 一段可执行断言输入，母版三段式：

```text
前置状态：输入场景 + 装载指针（C9/M2 指针或管线路径）
执行动作：协议路径（01/02/06/管线文档引用）
期望断言：硬（必须命中，违反 = FAIL）/ 软（倾向性观察，违反 = WARN 记档）
```

当前 v1 硬断言规则（捕获器 `execution_drill`）：

| 规则 | 语义 | 样例 |
|---|---|---|
| `fabricated_id` | 输出含装配真实编号集外的模块号（编造编号） | `M99` 不在 P03 装配集 |
| `browse_repeat` | 输出与源文本重合度高且无推进信号（浏览-复述） | 原文复制后无回合推进 |
| `no_citation` | 决策性断言无 §/编号/行号/章节引用（凭印象转述） | 「下一步应该……」无出处 |
| `semantic_misalignment` | 提及真实编号但语句职责词属其它模块（编号真实语义错位） | M00 被描述为时间推进 |
| `cross_pipeline_id` | 编号真实但属**其它管线**的装配集（跨管线串号，2026-10-05 扩） | P03 输出引用西幻包外的 `情感:M65` |
| `fabricated_asset_key` | 资产键编造——大写下划线键不在本装配允许集（2026-10-05 扩） | 输出引用不存在的 `SECRET_NOTES` 键 |

## 三、样本诚实标注纪律

- 每个 fixtures 文件带 `source_note`：样本来源显式标注 `inferred`（推断构造）或 `field001`（实测回执）——**推断样本不得伪装成实测**。
- NF-FIELD-001 回执原件（3 通过 + 8 失范明细）入仓后按 `field001` 增补/替换推断样本；未入仓前 fixtures 仅以推断样本 + 预留位运行，不做全称绿宣称。

## 四、回归触发点

- 协议层改动（01/02/06/03/04/community 或 verify 门禁变更）即触发全量演练回归：`bash verify.sh`（check12 discover 自动收编 `desktop/tests/fixtures/execution` + `test_execution_drill`）。
- 单集可复现执行：`PYTHONPATH=desktop/src python -m core.execution_drill desktop/tests/fixtures/execution/p03_drill_cases.json`

## 五、变异自检规程（演练的演练）

- fixtures 内 `guard: true` 样本 = 变异对照（把失范改写为合规形态），断言「不误捕获」——验证捕获器特异性；
- 验收门槛：注入 ≥3 失范样本捕获率 ≥2/3；guard 样本零误报；
- 防过拟合：演练全绿 = 「已覆盖样本绿」，非「协议无失范」全称绿——绿线只宣称覆盖面。
