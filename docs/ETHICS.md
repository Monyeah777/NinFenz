# 伦理与价值敏感设计（ETHICS）

> ⛔ 操作指令：本件是 NF-Final §3A D16 伦理/价值敏感设计的人读面；依据 §16A.3 与 IEEE 7000 / Value Sensitive Design 思想，判据 `desktop/tests/test_assurance_contract.py`。不声称伦理认证/合规。
> 状态：v1（G0 · 2026-11-14）· 配套：`docs/assurance/ASSURANCE_CASE.md`、`docs/RAID.md`、`PRIVACY.md`、`docs/ai/AI_GOVERNANCE.md`

## 方法论

- **Value Sensitive Design（VSD）**：先列直接/间接干系人与价值，再写价值冲突与设计回应，最后登记残余风险。
- **IEEE 7000 思想**：把价值当需求（可追溯、可评审），不是事后声明；冲突显式化，不静默取舍。
- 本仓定位：AI 辅助的长内容生产/装配工具；**不代替人做价值判断**，AI 输出须过人类复核闸门。

## 干系人与价值

| 干系人 | 关心什么 | 对应机制 |
|---|---|---|
| 使用者（内容生产者） | 可交付、可复现、数据不被外发 | 本地优先、离线核心、证据最小化（`PRIVACY.md`） |
| 内容读者 | 内容真实/可追溯、AI 生成可识别 | 证据链/模型卡/AIGC 标识（`docs/ai/AI_GOVERNANCE.md`） |
| 维护者 | 可维护、可审计、不被治理拖垮 | 双平面边界（check49）、自审计、质量债 |
| 第三方投稿人 | 条款与署名被尊重 | 投稿许可条款/署名（`LEGAL.md`、`REUSE.toml`） |
| 社会/监管（间接） | 不被用于欺骗/误导 | 不声称合规、缺项显式、外部操作不冒充 |

## 价值冲突与设计回应

| 编号 | 冲突 | 设计回应 | 残余风险 |
|---|---|---|---|
| EV-01 | 可复现（留证据）vs 隐私（最少留存） | 证据只存 digest/相对路径；保留/删除表；删除须可复原证据 | 用户主动写入敏感内容不可撤销 |
| EV-02 | 自动化效率 vs 人类自主 | 人类复核签名闸门；未签=PENDING；AI 不能签署 | 复核可能流于形式（外部监督不足） |
| EV-03 | 开放分发 vs 防滥用 | MIT 宽松许可 + 双用途清单 + 不提供攻击能力 | 下游用途不可控（许可免责） |
| EV-04 | 透明 vs 安全 | 阈值/机制公开、密钥/秘密不公开；文档给边界而非秘密 | 公开机制可能被规避（须持续审查） |
| EV-05 | 质量宣称 vs 不越级 | T0/T1 不写不可抵赖；映射只写 mechanism-alignment；禁用词判据 | 对外文案仍可能被误读（文档否定语境约束） |
| EV-06 | 本地优先 vs 协作需求 | 本地核心 + 适配器可选接外部服务 | 外部服务引入新的数据边界（`docs/legal/VENDORS.md`） |

## 伦理评审流程

1. 新增能力/数据面 → 过 `PRIVACY.md`、`docs/ai/AI_GOVERNANCE.md` 影响评估与 `protocol/*` 登记；
2. 价值冲突写入本件 EV 表（有回应与残余风险）；
3. 未关闭项进 `docs/RAID.md`（owner/复审）；
4. 出口/分发/合同类事项走 `docs/legal/`（不提供法律意见）。

## 不承诺

- 不声称伦理认证/合规/ISO 42001 合格；不代替使用者的价值判断；外部伦理审查未执行（属外部操作）。
