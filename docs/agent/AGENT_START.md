> 最后更新：2026-11-12 ｜ 入口链：本文件（开场）→ `docs/agent/AI_ROUTING.md`（选线）→ `docs/agent/agent_组装指令包_v0.2.md`（操作）。

## 一、先分流：使用者要什么

| 使用者说 | 你走哪条线 | 落点 |
|---|---|---|
| 「组装一个世界 / 按这个题材造一个完整版」 | 装配线 | `docs/agent/agent_组装指令包_v0.2.md`（工作流 `assemble`） |
| 「运行 / 装载一份现成作品」 | 执行线 | 按产物内 `##6. 装载指引` 开跑；产物不在手边先取件 |
| 「做一个模块 / 管线 / 资产包」 | 单件线 | `community/模板制作指令包.md` |

| 「NF 为什么这样设计」 | 理解线 | `docs/meta/DEEP_DIVE.md`（只解释原理，不替代操作规范） |

分流拿不准 → 先读 `docs/agent/AI_ROUTING.md`（A/B1/B2 三档能力边界），再回到本表。

## 二、按能力选档

| 档 | 能力边界 | 允许的动作 |
|---|---|---|
| A 线（agent / 有 API / 能执行代码） | clone、跑门禁、接 MCP | 全链：取货 → 装配 → 机器验收；MCP 面用 `nf serve`，工具与提示词清单见 `protocol/driver.json` |
| B1 线（能读 raw / 能下载） | 只能读文本件 | 按 `docs/agent/agent_组装指令包_v0.2.md` 取货组装；所有结论必须来自真读到的文本 |
| B2 线（纯粘贴，已免除） | 只有粘贴文本 | 自取 `docs/paste_card.md`（内容冻结于 v0.3，不随协议演进，产物质量自担）；不得假装读过仓库 |

**DRIVER OVERRIDE**（先于下文执行；机读真源 `protocol/driver.json`）：对应工作流已映射且 MCP 可用 → 改走 MCP 工具面（`assemble` 用 `assemble_guide` + `module_read` / `pipeline_read` / `asset_read`；`routing` 用 `spec_list` / `registry_search`），本文文本步骤不再执行。派发失败（工具报错 / 服务中途不可达）→ 如实报错并停止，不得回退执行文本步骤。仅当工作流无映射或本会话未启用 MCP 面时，才走文本 fallback。

## 三、开工三步（可复制执行）

1. 环境自检（A 线）：`python scripts/nf.py doctor`——退出码 0 表示关键件 / registry / schema / 核心库齐备；非 0 先按输出修复再开工。
2. 取货：按所选线读入口链——`07_官方核心出厂与社区预设导航.md` → `02_联动注册表.md` → `01_核心协议.md` → `06_Agent执行协议.md` → 目标领域包。缺件就向使用者要原文，或在装配记录里如实标注缺口。
3. 交付前机器验收：`python scripts/nf.py assemble "<需求>" --check <out.md>`——退出码 0 才算过机器面；再逐条过指令包的 `##7. 自检清单`。

> **铁律（宁缺毋滥）**：拿不准的模块号 / 资产键 / 依赖一律不编造——留空并注明，比写错更安全。

## 四、硬断言：先读后写

产物里引用的每一个模块编号、管线号、资产键，都必须来自你**实际读到的源文件**，或写成缺口（「待定 + 原因」）。凭记忆写职责、猜资产键、编目录号——任一命中即回炉重做。装配记录必须写明来源与缺口。

## 五、出口自检（与指令包 `##7` 同一把尺）

八段骨架齐？编号合法（官方核心用原号；社区题材用包内已登记编号；新建走 M91–M99 机制段或本包类内段）？模块要素齐？事件闭合？资产键真实？装配记录写明来源与缺口？——任一为否，先修正再交付。

产物 = 完整版 `.md`；交给使用者另存后，由任意叙事 AI 按产物内 `##6. 装载指引` 开跑。

## 六、停止条件（fail-closed）

- 读不到必需件且使用者也不给原文 → 停在缺口清单，不产出「看上去完整」的伪完整版。
- MCP 派发失败 → 如实报错并停止，不得静默回退。
- 你只是装配师：投稿入库归机器人 / 维护者；没有实际写入证据，不得声称「已入库」。
