# RFC 3161 可信时间戳

RFC 3161 Time-Stamp Protocol 用来证明“某个摘要在该时刻已经存在”。NF 只接受由调用方显式选择的 TSA 与信任锚，不预置公共根证书，也不把本机时钟冒充外部时间。

## 边界

- 时间戳绑定 subject 的 SHA-256，不证明内容质量、业务真实性或签发方身份。
- token 必须与原始 query 和同一 subject 同时校验；错 CA、错 subject、错 query 或篡改 token 一律失败。
- `nf-time-token/1` 记录内嵌 query 与 token 的 DER，但信任锚只记录摘要；消费方必须独立取得 CA。
- 没有有效 token 时，证据仍应标注 `time_proof=none`，不得写成可信时间。
- 普通门禁不访问公网 TSA。真实 TSA 调用是显式运行，不是 CI 隐式依赖。

## 生成

需要 OpenSSL 3.x。可通过 `NF_OPENSSL` 指定可执行文件。

```bash
python scripts/time_stamp.py create \
  --subject results/verification/example.txt \
  --tsa-url https://tsa.example.invalid \
  --ca-file /path/to/tsa-root.pem \
  --query-out example.tsq \
  --token-out example.tsr \
  --record-out example.time.json
```

命令执行：

1. 为 subject 生成 SHA-256 时间戳请求；
2. 显式提交到 `--tsa-url`；
3. 用调用方 CA 同时校验 token ↔ query、token ↔ subject；
4. 仅在全部通过后写 `nf-time-token/1` 记录。

## 离线验证

已有 query/token：

```bash
python scripts/time_stamp.py verify \
  --subject results/verification/example.txt \
  --query example.tsq \
  --token example.tsr \
  --ca-file /path/to/tsa-root.pem \
  --json
```

已有自包含记录：

```bash
python scripts/time_stamp.py verify-record \
  --subject results/verification/example.txt \
  --record example.time.json \
  --ca-file /path/to/tsa-root.pem \
  --json
```

机读 schema 位于 `protocol/schema/time_token.schema.json`。
