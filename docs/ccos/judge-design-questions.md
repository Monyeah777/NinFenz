# 判据设计十问（速查）

状态：**十一问**（2026-11-09）。写任何新判据前过一遍；每一问都对着本仓踩过的真坑。

## 一、它检查的**对象**存在吗

先确认被检查的东西有实体（对象 / 字段 / 文件 / 命令）。本仓教训：`version_chain` 缺失时，三层设计都被否，
因为「没有可核对象」——判据写出来只是自述。

## 二、断言的**输入**从哪来

抽取口径宽一格，判据就退化。本仓教训：查文档路径的宽正则产生 **118 条假红**，收窄成「必须带根前缀」后 59 条全真。

## 三、**池子边界**划清了吗

「什么算在场」「什么算指向」必须先定义。本仓教训：孤儿判据把 `docs/` 计入池，写一篇清单文档就空转；
把脚本自身计入池，每个脚本的 usage 行都自我满足。

## 四、会不会**自指**

判据若扫描包含自身的文本，往往自证为真。本仓教训：路径旗标棘轮第一版把自身纳入扫描，冻结表立刻被判「已覆盖」。
修法：扫描时显式排除本件。

## 五、它**红过**吗

没红过的判据无法证明有杀伤力。两条路径：**变异测试**（造一次红）或**真红记录**（把历史红写进文档）。
本仓现状：内容判据有变异探针（5 判据 / 15 变异体），引用面判据有三次真红记录。

## 六、它**被生产路径调用**吗

函数级判据若只被测试调用，本质上仍是文档里的承诺。本仓教训：证人核对写了三周，但生产路径不传 `root`，
CLI 上的幽灵证人一直能过；把 `session.step(root=)` 接上后才真正生效。

## 七、覆盖的是**能重算的量**吗

文档数字判据只该覆盖能从数据件重算的量（层数 / 域数 / 门数 / 项数）。规范类计数（「7 个系统调用」）刻意不判——
那会变成「规范复述自己」。

## 八、数字或名单**会不会漂**

会漂的东西要么有同步机制（生成脚本 + `--write`），要么进棘轮（冻结表 + 新增即红 + 修好须删）。
本仓教训：冻结表只增不删会变成「永久豁免名单」，所以必须配一条「修好须删条目」的反向判据。

## 九、它的**失效方式**写下来了吗

写不出失效方式的判据，等于没被理解。本仓的《判据族谱》要求每族写「失效方式」一栏，
这正是从「判据有没有红」升级到「判据会不会骗人」。

## 十、明天代码改了，**谁会先红**

最后一个问题：如果明天有人改错代码，是这条判据先红，还是别的（或没人）先红？
若答案是「没人」，那这条判据的覆盖实际上不存在。本仓做法：把「哪条判据守着哪个不变量」写进《双核不变量》与《族谱》。

## 十一、它**只查了一个方向**吗

集合类判据（「A 必须都在 B 里」）最容易只写一个方向。本仓教训：一次性审计清单的判据只查了
「冻结集 ⊆ 文档」，于是文档多列几个脚本也不会红——两边对同一事实的表述不一致却无人发现。

做法：**双向各写一条断言**，并让「多」和「少」各有独立失败信息（否则报错时看不出是哪个方向）。
第 182 轮的台账问题（红结论混进绿表）也是同一形态：只核了「绿行存在」，没核「红行不在绿表里」。

## 用法

新判据提交前自问十问；答不上第 2、3、4 问说明**口径没想清**，答不上第 5、6 问说明**效力没验证**，
答不上第 9、10 问说明**边界没划清**。十问都答得上，判据才算落地。
