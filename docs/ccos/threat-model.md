# CCOS 威胁模型 v0（能证明什么、不能证明什么）
> ⛔ 操作指令：阅读即执行——本文含可直接执行的复核命令与判定，勿当资料阅读。
> 最后更新：2026-11-06
> **Status**: Draft v0 · **性质**: 边界声明（与 ABI 的「实装状态」逐条对应）

## 为什么要写这一节

中立第三方仲裁的前提不是「我们很安全」，而是**把断言的面说清楚**：哪些性质由密码学判据强制，
哪些只到工程纪律为止，哪些明确**不承诺**。本文与 ABI 的每个调用、证据包文档的每条判定一一对应；
任何一条「能证明」都必须能指到实现与复核命令。

## 信任根与本机边界

- 信任根是**本机运行的这份代码 + 本机的密钥材料**。CCOS 不引入外部权威（无 CA、无时间戳服务、
  无在线吊销分发），因此它判的是「**这份制品与这份证据是否自洽**」，不是「它是否被某个权威签过」。
- 门禁单进程引擎会把目标仓库 verify.sh 里内嵌的 Python 当本机进程代码执行（CWE-94）。故默认**只信
  当前安装根**；外来仓库一律拒绝，需显式信任开关自担风险。信任标志只在执行区间内生效、出区间还原
  （环境泄漏即绕过信任门）。
- 常驻守护在代码变化时会把 core 模块从 sys.modules 摘掉重载——**判据必须以运行时对象为准**，
  不能用导入时抓到的旧对象做观测（否则得到「看着像 bug 的读数」）。

## 攻击者模型

| 编号 | 攻击者能力 | 判据面对 |
|---|---|---|
| A1 | 改证据包任一成员字节 | 成员摘要 + 叶/根复算 → invalid |
| A2 | 伪造或替换信封（签名或 MAC） | 每份信封都必须过 + 最弱环定强度 → invalid |
| A3 | 增删或重排条目，或删掉链段、置空链头 | chain 段必填且自洽 → invalid |
| A4 | 把吊销表写坏或换成别的形状 | 坏件与形状不符**不**当「无吊销」→ invalid（不是放过） |
| A5 | 重放别的仓或别的版本的证据包 | 主体摘要绑定仓相对路径与内容口径；根不重合 → invalid |
| A6 | 让证据过期但改本地时钟 | 时效判据依赖本机时钟 → 只能防老实时钟（缺口 G3） |
| A7 | 供应链换包（镜像站/包镜像） | 不在密码学面内：只提供清单/来源证明的**核对**能力（缺口 G5） |
| A8 | 拿到 hmac 密钥 | 强度词表如实降级：hmac 级不是签名，泄漏即失效 |
| A9 | **敌意容器**：成员路径带双点段 / 重名成员 / DEFLATE 炸弹 | 路径安全闸门 + 重名判死 + 单件/整包解压上限 → invalid（验证器必须敢验敌意输入） |

## 逐条性质：能证明 / 不能证明

| 性质 | 结论 | 依据 |
|---|---|---|
| 证据包**未被改过** | 能（SHA-256 + RFC 6962 域分隔） | 证据模块；`nf evidence verify`；攻击矩阵含成员/根/证明篡改 |
| 条目**顺序未被改** | 能（透明日志链头） | chain 段必填 + 链头重算；矩阵含删链段/空链头/改序 |
| 每条内容**被回执背书** | 能（每份信封必过；多出来的字节判死） | 信封全过 + 未登记成员 → invalid |
| 证据**当前有效** | 能到「记录时刻 + 本机时钟」为止 | 时效判据；不承诺外部时间权威 |
| 证据**已被吊销** | 只能证明「**拿到的吊销表**里命中」 | 本仓无在线吊销分发（G2） |
| 制品的**强度等级** | 能（最强且通过的那一档） | 强度词表；缺密钥或缺工具**不**降级冒充 |
| 内容**对不对**（合规/事实/情感） | **不承诺**（不跑模型、不做检测） | ABI 非目标 |
| 模型**行为**与**训练数据访问** | **不承诺**（不评测模型行为、不追溯训练数据） | ABI 非目标 |
| 载体**物理绑定**（防截屏/防转贴） | **不承诺**（PNG iTXt / JPEG APP15 只写可见文本段，无水印/无抗转码；其它格式无载体写入） | ABI §1 状态标注 |
| 第三方**零依赖复验** | 能（单文件验证器，fail-closed） | `scripts/nf_verify.py`；双实现一致性判据 |
| 过了**哪条策略**（decision） | 能到「与一次 cc_check 判定自洽且被签发面覆盖」；**不**证明策略内容正确 | decision 绑定 + 攻击矩阵 decision_policy_swap / decision_strip |

## 已知缺口（按优先级）

- **G1 外部锚点（已部分实装）**：打包可声明 `--anchor {count, head}`，复验可用同一份材料核对
  「包没有被截断成更早版本」（截断/分叉/形状不对都判 `invalid`）——但**「锚点从哪来、可不可信」
  不在本 ABI 内**，且调用方不提供锚点时只能 warning、不能判死。锚点的分发与见证仍是缺口。
- **G2 吊销分发（已部分实装）**：`nf-revocation-feed/1` 给吊销表套了「issuer + 单调 seq +
  前序摘要 + hmac」信封，能验来源、能防回滚/分叉（`nf evidence revocations sign|verify|merge`，
  见 [revocation-feed-v0.md](revocation-feed-v0.md)）。残留：**仍是拉取式**——没有发布/订阅通道，
  「签发方已撤销但你没收到」无解；且 hmac 是对称的，跨组织来源证明还得走公钥面。
- **G3 无可信时间戳（已做诚实闭环，仍缺外部权威）**：时效判据吃本机时钟，回拨即可绕过「已过期」。
  2026-11-07 起判定面如实标注 `time_proof`（`none` = 本机时钟；`pinned` = 调用方给定、可对账）
  + `time_basis`，并在包带有效期且未给 `--at` 时给显式 warning——不假装时间可信。仍未做：
  RFC 3161 时间戳 token 的签发与校验（需外部 TSA）。
- **G4 `cc_label`：声明层 + sidecar 回退 + PNG/JPEG 载体已实装；水印与多格式仍缺**：`nf-label/1` IR
  能校验「该有哪些标识、缺哪几条」；sidecar（`nf-label-sidecar/1`）把声明与对象摘要绑定，对象一变即判
  过期；`nf label embed` 把 IR 写进 **PNG iTXt 块**（可读回 / 不改像素 / 块结构合法）。但那是**可见文本
  载体**——任何人可剥掉，抗裁剪/抗转码/抗截屏（真水印）**不承诺**；JPEG/MP4/PDF 无载体，只能走 sidecar
  且 `embedded=false`。
- **G5 供应链核对（已部分接入 gate）**：发布结论器现在**先跑**供应链核对（站点件数/体积 vs payload
  清单、根 llms-full 投影逐字节一致），不一致即不产出「可发布」。残留：payload 清单自身的来源证明
  （SLSA/OIDC 签名）仍靠发布线外置命令核对，不在本 gate 内。
- **G6 零依赖验证器对 ssh-sig / sigstore 一律 fail-closed**：判不了就报 invalid，不猜。

## 复核（可执行的攻击矩阵）

```bash
# 证据线：攻击矩阵（含 A1–A5 的逐条变体；任一条不达期望即 exit 1）
python scripts/nf.py evidence bench

# 双实现一致性：真源与零依赖验证器必须同判（含缺链段/坏吊销表）
python -m unittest desktop.tests.test_evidence

# 发布结论（干净树 → 结构面 → 测试面）；注意 payload 需与 HEAD 一致
python scripts/release_conclusion.py --dry-run
```

## 不承诺（清单式，避免误读）

不做 DRM、不做水印、不做内容审核、不做身份认证、不做反截屏、不做防内鬼（拿到密钥的人可以签任何
东西）；不宣称外部权威背书。所有判定都只对**输入的那份证据包**负责。
