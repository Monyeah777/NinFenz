## 一句话定位

NF 认知驾驶舱不是“写得更长的提示词”，也不是替模型打分的评审器。它是一层**模型无关的认知生产基础设施**：在模型生成前后，动态决定调用哪些元认知方法、给模型什么上下文、如何校验阶段结果、状态失败时怎样停止或回退，以及最终产物携带哪些证据和方法轨迹。

驾驶舱不试图改变模型参数，而是控制模型所处的认知环境。其核心命题是：

> 模型能力不是唯一变量；方法组合、上下文组织、约束强度、状态一致性和证据交接，同样决定最终产出。

## 与提示词工程的区别

| 提示词工程 | NF 认知驾驶舱 |
|---|---|
| 预先写死一套角色、步骤和输出格式 | 每次根据任务画像重新选择 1–3 个原子方法 |
| 方法隐藏在自然语言里，不可独立验证 | 每个方法原子有执行器、输出合同和轨迹 digest |
| 一次调用失败后重新问一遍 | 状态、候选、选择、执行和校准进入事务边界 |
| 上下文靠手工拼接 | 按分区预算、任务角色和证据可信度检索 |
| 输出好坏依靠主观感觉 | 外部盲评协议与预注册统计，不把评分放回驾驶过程 |
| Agent 可自由越界行动 | 工具、补丁、路径、预算和停止条件均受约束 |

驾驶舱的中心不是“更聪明的 prompt”，而是“让任何足够强的模型在当前任务上进入更合适的认知形状”。

## 总体架构

```text
任务输入
  → 任务画像 / facet 义务
  → 当前状态与缺口
  → 安全候选组合
  → 单轮动态选择
  → 原子执行与状态提交
  → 一致性 / 证据 / 停止检查
  → 任务原生交接
  → 外部质检、盲评与人工复核
```

### 1. 元认知原子层

当前注册 33 个确定性原子执行器，覆盖知识表征、拆解、关系、比较、反例、审计、规划、监控、综合和校准等基本认知动作。原子不是抽象标签，`execute_atom()` 会返回：

- `status`：通过与失败；
- `output`：结构化阶段产物；
- `error`：失败原因；
- `input_digest` / `output_digest`：输入输出绑定。

任何未知原子、缺失执行器或输出类型不匹配都会 fail-closed。原子层向上组成 14 个方法节点，并为 M0–M4 元梯度提供稳定映射。

### 2. 方法节点与两级管线

- **内容管线**：10 个节点，负责从拆解、因果、反例到综合和验证。
- **元管线**：5 个节点，负责方法路由、方法审计、过程监控、判据框架审计和证据标准选择。
- **元梯度**：区分对象级、方法级、监控级、框架级和元规则级认知，避免把“执行方法”和“审计方法是否合适”混为一谈。

元管线不是内容管线之后的固定装饰，而是持续回答：当前方法是否适用、判据是否完整、预算是否仍可控、证据标准是否与任务类型一致。

### 3. 单轮动态编排

驾驶舱不预生成一份贯穿全程的固定计划。每一轮根据以下状态重新编译：

- 任务类型与领域画像；
- 当前已满足和未满足的 facet；
- 已执行方法的历史；
- 上轮状态增量；
- 失败、冲突和开放问题；
- 剩余回合、时间和上下文预算。

候选组合被限制在最多 3 个原子、最多 5 个候选中；搜索有展开数和生成数上限。该设计避免“33 原子全排列”造成组合爆炸，也避免模型在安全候选集之外自由发挥。

### 4. 约束式选择

模型单轮只返回受约束结构：

```json
{
  "choice": 0,
  "reason": "先补齐结构与风险",
  "stop": false
}
```

不在候选范围内、带内部评分、缺少理由、越界 `choice`、非法停止或额外计划字段都会被拒绝。模型可以选择“下一步怎么想”，但不能私自扩大动作空间。

### 5. 上下文与证据工程

上下文包按用途分区，而不是把全部材料塞进一个 prompt：

- 固定目标和协议；
- 当前状态视图；
- 方法卡片与输出合同；
- 域图邻域；
- 有界证据摘录；
- 方法记忆与未解问题。

运行时维护总量、单包和分区预算，并报告稳定前缀与动态部分的 digest。证据按 `local-trusted`、`derived`、`external-advisory` 等角色隔离：外部材料可以提供上下文，但不能自动升级为本地事实。

### 6. 状态、事务与恢复

每一轮是一次受控事务：

1. 选择候选；
2. 绑定当时的上下文与状态 digest；
3. 执行原子；
4. 校验输出类型与闭合条件；
5. 提交新状态；
6. 追加事件账本；
7. 更新可靠性账本。

会话账本采用哈希链、并发锁和原子写。恢复时可以从初始状态和事件序列重新执行，验证上下文、原子轨迹、状态增量与校准事件是否一致。没有进展的计划、重复状态环和超过边界的运行会停止，不允许无限递归。

### 7. 结构化交接

驾驶舱完成的是“可继续工作的认知状态”，不是一段孤立文本。交接会携带：

- 任务画像和已满足 / 未满足义务；
- 方法轨迹和状态 digest；
- 关系、风险、综合与冲突消解；
- 证据摘录、域图和来源角色；
- 未解问题和下一步建议；
- 结构化弃权原因；
- manifest、journal 和 runtime digest。

因此下游人工、另一个 Agent 或后续生产工具可以继续工作，而不需要猜测上一轮“想到哪里了”。

### 8. 质量证明与盲评

驾驶舱内部**没有质量评分**。方法是否真的带来质量增量，由独立离线 A/B 协议回答：

- 同 prompt、模型、seed 严格配对；
- 分析阈值、样本门槛和停止点预注册；
- 评审包隐藏 arm、model 和 seed；
- 检查 judge 一致性、分模型结果和功效；
- 固定 stopping rule，禁止看到显著性后提前停；
- 实验、ballot、分析和 bundle 用内容摘要绑定。

盲评结论不会回写成驾驶过程中的“分数”，只在实验报告中作为外部证据存在。

## 关键安全边界

- 外部模型默认不参与核心验收；
- 网络断开、输入损坏、状态篡改或执行器缺失时 fail-closed；
- 凭据扫描覆盖 prompt、注入、patch、response、handoff 和 A/B ballot；
- 路径、上下文大小、搜索空间、事件数、存储大小均有上限；
- `thought_patch` 只能修改当前方法允许产生的键，不能无界改写状态；
- 人工复核记录不能被自动生成，也不能由 agent 伪造 approve。
