## 2. 覆盖与解析口径

- 模块：**248 件**模块文档全量可寻址（`04_模块库` 13 + `community/*/modules` 235）——**含无机读块的存量内容模块**（按标题/文件名 id 解析，`has_machine_contract` 如实标注）；同号限定（如 通用:M10 / 生存:M10）须用全限定 id。
- 管线：**114 条**（03 官方 3 条 P00/P01/P90 + `community/*/pipelines` 111 条），按 Pxx 或仓库相对路径解析（**跨包可能同号，路径解析优先**），路径白名单防越界。
- 资产：community 包 assets + 05 用户自定义，**多键登记**（文件名令牌 ∪ 正文键声明 `` `KEY` `` / `` "KEY": `` / `` ## KEY ``），每键独立资源条目 + 可选包解析。
- 未知目标 → `-32602` 参数级拒绝（消息带修复指引）；全部只读、无写面。

## 3. 取用纪律（硬断言口径）

- 装配输出凡涉及模块职责/事件/资产内容，必须先经内容工具或 `resources/read` 读取真实正文——不得凭记忆/印象写未读取内容（对齐 execution_drill **R1–R8**；硬断言规则现行 **6 条**：fabricated_id / browse_repeat / no_citation / semantic_misalignment / cross_pipeline_id / fabricated_asset_key）。
- 资产/模块/管线引用如实标注来源（文件路径/§/行号）；编造编号、职责错位、无引用决策均属失范（对应 drill 失范类别）。

## 4. 与既有设施的关系

- 数据源仍为仓库只读扫描，不与 C2 只读安全层冲突；资源/工具/引导三面同源同一套解析（无第二份真值）。
- 外部标准客户端实测仍按 STRATEGY 封闭期冻结（E3 口径），本规范为内部可执行面。
- **默认面**：`nf serve` = 实时仓库面（无需快照）；快照面（`nf run --fmt mcp` → `nf serve <快照>`）仅在固化某次成果面时需要。
