## 现状对照（2026-11-14 · 以 `nf postmortem` 与协议件实读为准）

| 面 | 当前口径 | 复核方式 |
|---|---|---|
| 必填四段 | 现象 / 影响 / **根因（须指向机制）** / 行动项 | `nf postmortem check` 的四段断言 |
| frontmatter | `id`（`PO-9xxx`）/ `title` / `date` / `trigger` / `status` / `refs` | 本文头部 + `test_publish_boundary.py`（公开面只留模板） |
| 行动项要求 | 每条必须带 **负责人** 与 **判据**（怎样算完成） | `nf postmortem check` 的核心断言 |

| 公开面边界 | 真实复盘件在私有 Plan 仓 `governance/decisions-archive/postmortems/` | `2026-10-25` 作者裁决（`decisions/ADR-0000-决策记录外置到私有仓.md`） |

本文是**模板**：现象/影响/根因/行动项正文里的示例文字可直接替换；`trigger: check35` 与 `refs` 也必须换成真实件或 `checkN`。
本页**不钉门禁条数**；四段与行动项要求由 `nf postmortem check` 判定，不以本文为准。

## 复现与引用口径

```bash
python scripts/nf.py postmortem check postmortems/PO-9000-示例-复盘模板.md   # 单件机检（四段/无指责/机制/判据）
python scripts/nf.py postmortem verify                                       # 声明 + 全部复盘件
python -m pytest desktop/tests/test_postmortem.py desktop/tests/test_publish_boundary.py -q
```

（机检提示：`nf postmortem check` 会把**全文所有** `- ` 开头的行当作行动项，所以模板里除「## 行动项」外**不要**用项目符号列表——本页末尾几段刻意写成散文。）

写真实复盘时：**现象**只写可观测事实；**根因**必须落到机制（流程/判据/接口），**不写人名**；**行动项**每条给出负责人与判据。
