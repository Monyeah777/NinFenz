What the five parts cover

The judgment is split into parts A–E, each with PASS / WARN / FAIL / NA and supporting evidence.

A · Explicit label

Whether a readable “AI-generated” or synthetic-content notice exists in the text, interface or file, and whether its wording and placement meet the requirements.

B · Implicit label fields

Whether metadata carries the seven-field label structure, producer information and reserved fields, and whether keys and values are internally consistent.

C · Security protection data

Whether producer security fields, hash binding and signature material are present and can be tied to the content.

D · Content binding

Whether the label is bound to the file content and remains detectable after content replacement or splicing.

E · Filing materials

Whether explicit samples, implicit samples, content digests and binding records are sufficient for internal archiving or a filing explanation.

Evidence and remediation

Every finding includes an evidence excerpt and a remediation hint; the report ships with commands so the same path can be re-run.

Five-minute checklist

  1. The file type is supported and the file is neither encrypted nor damaged.
  2. Explicit label: can you find an “AI-generated” notice in the file or interface.
  3. Implicit fields: does metadata contain an AIGC / Label structure and producer information.
  4. Binding: record the file hash, generation time and tool version for recomputation.
  5. Remediation trail: keep both the before and after files plus command output.
