从治理要求到发布证据，只差一个可执行层

AI governance 平台定义政策，observability 平台观察运行，安全平台拦截攻击。NinFenz 负责另一件具体的事：在内容对外发布之前，证明它满足明确契约。

01 / CONTRACT

版本化契约

把章节、字段、参数、审批和禁止模式写成可复现的规则，而不是散落在手册里的要求。

02 / GATE

确定性门禁

CLI、MCP、Agent 或 CI 执行同一套检查。失败返回 rule ID、位置和修复提示。

03 / EVIDENCE

可审计证据

JSON 与 HTML 报告可归档、可复验，并可与 checksum、provenance 和 attestation 结合。

04 / RELEASE

发布前决策

让内部审计、客户交付和采购安全问卷拿到同一份证据，而不是“我们检查过了”。

面向真实 AI 输出，不是抽象治理看板

适合这些场景

  • Agent 生成企业报告、工单总结、发布说明或知识库内容
  • API reference、runbook、migration guide 和 security policy 的发布门禁
  • 需要把控制证据交给客户、内部审计或企业采购的 AI 产品团队
  • 已有 governance / evaluation 工具，但缺少内容发布执行层的平台

明确不做什么

  • 不做全企业 AI inventory 或 shadow AI 发现
  • 不做 DLP、IAM 或实时 Prompt 攻击拦截
  • 不做模型漂移、公平性或红队评测
  • 不把 PASS 说成事实正确、法律合规或安全认证

Technical definition

宁封子（NinFenz，简称 NF）是内容契约层（content contract layer）：用「协议 + 确定性门禁 + 可验证产物」把「AI 稳定产出长内容」变成可装载、可质检、可复现的工程；协议本体域中立、模型无关，叙事只是官方第一个域包。

技术机器面：/llms.txt · /llms-full.txt · /facts.json · /nf.txt · /agent.txt

常见问题

Community 真的免费吗？

核心代码采用 AGPL-3.0-only，可用于内部部署和内部 CI。需要闭源嵌入、正式 SLA、商业合同或企业采购时使用商业许可。

和 AI governance 平台什么关系？

NinFenz 是治理政策和真实输出之间的执行与证据层，不替代 AI inventory、风险评分、模型观测或安全平台。

会检查事实吗？

不会。它检查是否满足明确契约。事实正确性、法律判断、发布适用性仍由人和对应专业流程负责。

可以私有化吗？

可以。核心校验和报告均为本地优先。企业商业许可包含私有化部署支持和安全问卷配合。
