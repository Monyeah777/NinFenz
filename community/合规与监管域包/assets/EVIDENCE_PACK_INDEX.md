# 证据包索引模板 · 合规与监管

> 用途：AI 内容合规证据包的**目录与自检模板**——把「哪条判据、由哪份证据、哪个角色、哪次复核支撑」列成索引表，使证据包可被第三方按行抽查。
> 资产键：`EVIDENCE_PACK_INDEX`｜消费方：`gate_profiles/regulatory-strict.json`（全部 clause 的证据落点）、M02 收口与派生、人工评审。
> 定位：索引是证据包的**导航面**；它只指向证据，不复制证据正文（单一真相源）。

## 2. 索引自检（交付前逐项）

1. 每行「证据文件/章节」在证据包内**真实存在**（章节标题或表头可 grep）。
2. 每行「profile clause」在 `gate_profiles/regulatory-strict.json` 的 `clause_id` 集合内（无编造编号）。
3. 每行「责任角色」在资产 `HUMAN_OVERSIGHT` 角色表内。
4. 每行「复核日期」为 ISO 8601。
5. 索引行数 ≥ 证据包要求的证据类别数（本模板 10 行）。

## 3. 与证据包成品的关系

- 证据包成品应至少有：合规声明、AI 披露、标识、数据来源、风险分级、人类监督、审计日志、保留期与联系人、敏感信息、版本变更十类章节/表。
- 成品由 P98 装配流产出（`nf assemble --build`），索引模板即其目录骨架。
- 证据包 `--check` 通过后，索引中的复核日期与版本表须同步。

## 4. 机检映射（profile → 本资产）

| profile clause | 本资产对应段 | 判定 |
|---|---|---|
| `STRUCT-DOCTYPE` | 证据包 `> 文档类型：compliance_evidence_pack` | 类型在白名单 |
| `STRUCT-H1` | 证据包唯一 H1 | H1 数 = 1 |
| 其余 clause | §1 索引表的 clause 列 | 索引覆盖全部 clause_id |

## 5. 使用边界

- 索引不构成证据本身；第三方核查仍须回看被指向的章节与日志。
- 复核日期与责任人属组织内部管理信息，对外披露须脱敏。
- 本模板不覆盖外部审计的抽样方法。
