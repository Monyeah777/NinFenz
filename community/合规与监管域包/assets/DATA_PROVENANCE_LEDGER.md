# 数据来源与授权记录模板 · 合规与监管

> 用途：AI 内容合规证据包的**来源章节模板**——登记每条内容/数据的外部来源、授权方式与用途，使「这段内容依据什么数据、凭什么可用」可逐条回答。
> 资产键：`DATA_PROVENANCE_LEDGER`｜消费方：`gate_profiles/regulatory-strict.json`（clause `DATA-SOURCE-SECTION` / `DATA-SOURCE-TABLE` / `DATA-LICENSE`）、M01 口径登记、人工评审。
> 定位：本表是**来源台账**，不是授权文件本身；授权凭证（合同、许可文本、书面同意）按证据包索引另行归档。

## 1. 来源登记表模板

| 数据来源 | 授权方式 | 用途 |
|---|---|---|
| 自有语料（<业务线>） | 内部授权（组织所有） | 生成营销文案的检索底料 |
| 公开许可数据集（<名称/版本>） | CC BY 4.0 许可 | 模型评测与样例生成 |
| 客户提交材料 | 客户书面同意（合同附件 <编号>） | 仅为该客户生成内容，不跨客户复用 |
| 第三方 API 返回结果 | 服务条款 + 数据处理附录 | 内容生成时的实时事实核验 |

## 2. 授权类型词表（只登记可追形态）

| 授权形态 | 可追证据 | 不可用写法 |
|---|---|---|
| 内部授权 | 组织内部授权文件编号 | 「公司自己的数据」 |
| 开放许可 | SPDX 许可证标识（如 `CC-BY-4.0`、`MIT`、`Apache-2.0`） | 「网上公开的」 |
| 书面同意 | 合同/同意书编号与签署日期 | 「客户知道」 |
| 服务条款 | 条款版本号 + 生效日期 | 「对方没反对」 |

## 3. 登记纪律

1. **一来源一行**：来源名不写「互联网」「公开资料」这类无法定位的说法。
2. **授权可追**：授权方式必须是上表词表之一，并给出可查证的凭证编号。
3. **用途受限**：用途列写明该数据**只能**用于什么；跨用途复用须重新登记。
4. **出境与再委托**：涉及数据出境或再委托处理时，在用途列注明「出境评估编号 / 受托方」，不留空。
5. **无授权即不入包**：无法给出授权证据的数据，不得进入证据包。

## 4. 机检映射（profile → 本资产）

| profile clause | 本资产对应段 | 判定 |
|---|---|---|
| `DATA-SOURCE-SECTION` | 证据包「数据来源」章节 | 章节存在 |
| `DATA-SOURCE-TABLE` | §1 三列表 | 表头 数据来源/授权方式/用途 |
| `DATA-LICENSE` | §1/§2 授权表述 | 出现「授权」或「许可」 |

## 5. 使用边界

- SPDX 标识只表示许可**类型**，不代替许可正文的适用判断（版本、例外条款须人工核）。
- 本表不覆盖数据安全技术措施（加密、访问控制），该面见资产 `AUDIT_LOG_SCHEMA` 与 `RETENTION_CONTACT`。
- 「公开可得」不构成授权依据；公开性与可用性是两个概念。
