# 影响评估清单（DPIA 等价形）· 合规与监管

> 用途：AI 内容合规证据包的**评估章节模板**——在内容上线前逐项回答影响评估问题，形成可复核的判定与整改记录（隐私影响评估 DPIA 的等价机检形）。
> 资产键：`IMPACT_ASSESSMENT`｜消费方：`gate_profiles/regulatory-strict.json`（间接：`PRIVACY-SECTION` / `NIST-AIRMF-RISK-*` 的证据来源）、M01 口径登记、人工评审。
> 定位：清单是**判定框架**，不提供法律判断；评估结论由责任人签署。

## 1. 评估清单（条目键可 `asset_get('IMPACT_ASSESSMENT','IA-xx')` 寻址）

| 条目键 | 评估问题 | 判定口径（可机检） | 输出物 |
|---|---|---|---|
| `IA-01` | 内容是否由人工智能生成或合成？ | 是 → 必须登记披露与标识 | 披露表行 + 标识表行 |
| `IA-02` | 是否涉及个人信息或敏感信息？ | 是 → 最小化、去标识化、保留期三件齐备 | 敏感信息章节 + 保留期表 |
| `IA-03` | 是否面向未成年人或脆弱人群？ | 是 → 人类监督前置审批 | 监督表行（角色/动作/触发条件） |
| `IA-04` | 是否可能造成重大权益影响？ | 是 → 升为高风险 | 风险登记表行（高风险） |
| `IA-05` | 是否涉及深度合成（人脸/声音/场景）？ | 是 → 加深度合成声明 | 披露章节深度合成段 |
| `IA-06` | 数据来源是否全部有授权证据？ | 否 → 不得入包 | 来源台账行 + 凭证编号 |
| `IA-07` | 是否有可触达的申诉与更正渠道？ | 否 → 不得上线 | 联系人表行 |
| `IA-08` | 出问题能否回放（日志 + 版本）？ | 否 → 不得上线 | 审计字段表 + 版本变更表 |

## 2. 判定记录模板

| 条目键 | 判定 | 依据 | 责任角色 | 完成日期 |
|---|---|---|---|---|
| `IA-01` | 是 | 本内容由 AI 生成，见披露表第 1 行 | 内容负责人 | 2026-10-20 |
| `IA-02` | 否 | 仅含公开企业信息，不含个人信息 | 合规联系人 | 2026-10-20 |
| `IA-08` | 是 | 审计日志含 `trace_id`，版本表可回放 | 平台负责人 | 2026-10-21 |

## 3. 评估纪律

1. **先判定后上线**：`IA-01` / `IA-02` / `IA-06` / `IA-08` 任一未判定即不得上线。
2. **判定可核**：依据列须指向证据包内的具体表行或资产条目，不写「已评估」。
3. **整改留痕**：判定为「否」而实际需要整改的，整改记录进版本变更表。
4. **复审触发**：内容类型、来源、受影响人群任一变化即触发复审，复审结果追加新行。

## 4. 与 profile 的关系

- 本清单不直接绑定单一 clause；它是 `PRIVACY-SECTION`、`NIST-AIRMF-RISK-*`、`OVERSIGHT-*` 的**证据来源**（判定为「是」时须产出对应章节/表行）。
- 评估记录缺行不影响单条 clause 判定，但会被 `STRUCT-DOCTYPE`（文档类型白名单）排除在证据包之外。

## 5. 使用边界

- 本清单是 DPIA 的**等价机检形**，不替代法定的隐私影响评估程序与监管沟通。
- 判定责任在组织；NF 只提供结构与判据。
