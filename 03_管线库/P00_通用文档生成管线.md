# 管线 P00 · 通用文档生成管线

> 域无关的**通用文档生成骨架**（元管线）：以“装载 → 语境推进 → 实体状态 → 内容生产 → 决策 → 装配 → 一致性 → 素材 → 输出”九层作为任何领域内容生成的最小结构。本管线不预设任何领域语义；官方两支在册实例 = **P01 标准管线**（通用标准装配）与 **P90 结构化装配管线**（非文本域的实证装配），社区派生管线以 **02_联动注册表.md** §8 登记为真源——本骨架不另立实例清单（I5 真相唯一）。
> 使用方式：新领域 = 以本骨架为模板派生新管线（复制本文件 → 按 01 §2 改 id/name/层名/挂载/flow/tags → 02_联动注册表登记）→ **引擎不改（I5）**。
> 注：管线 id 命名空间（P00/P01/P02/…）与文件内层位 id（P00–P80 九槽骨架）相互独立——每条管线文件内均以 P00–P80 声明层位，**层名与模块挂载才是该管线的领域装配**。

## 运行规则

- 本管线是**派生模板**：default/allowed 为空表示不锁死挂载（01 §2：allowed_modules 为空 = 不限）；派生时按领域填写实际模块。
- 实例示例：P01 标准管线把 P00–P80 九槽命名为“装载 / 语境推进 / 实体状态 / 内容生产 / 决策 / 装配 / 一致性 / 素材 / 输出”并挂载官方核心机制模块；其它域包派生管线按自身域命名同名九槽。**层名与挂载的领域特化正是实例的正常形态**，反证层名可按领域自由替换；完整实例清单以 02_联动注册表 §5/§7 与 §8 登记为准。
- 新领域接入三步：
  1. 复制本文件派生新管线（改 id/name/层名/default/allowed/flow/tags）；
  2. 新模块按 01 §2 声明：官方核心机制件进 04_模块库（07 §1，件数为基线、可增不减），题材/域包模块进社区包 modules/（编号走 M91–M99 机制段或本包 R2 独占类别的类内段 <类别>:Mxx，01 §6 R2 / 07 §5）；或直接复用通用类 M00/M23/M50/M80；
  3. 在 02_联动注册表登记挂载表与 execution_order → Agent 即按注册表调度（I5），**引擎代码不改**。
- structure 可扩展：01 §2 支持 linear/loop/branch/fold/parallel/nested/custom/techdoc（值域真源 = protocol/schema/pipeline.schema.json 的 structure.type enum），本骨架示范 linear；需要分支/并行/嵌套/折叠结构时按 01 §2 自定义 structure.type 与 flow（含 condition）。
