# 管线 P90 · 技术文档生成管线

> 实例声明：本管线是通用骨架 **P00**（03_管线库/P00_通用文档生成管线.md）在**结构化装配领域**的实例装配——复制 P00 派生（改 id/name/层名/挂载/flow/tags → 02_联动注册表登记），**引擎不改（I5）**。
> 领域：结构化装配实证（P00 骨架派生实例——派生规程见 06_Agent执行协议.md §10「管线增删改细则」）。九层位 id（P00–P80）与管线 id（P90）相互独立，层名与模块挂载是本管线的领域特化。

## 读法（本文件怎么用、怎么验）

- **这是什么**：P90 是 P00 骨架在**技术文档领域**的派生实例——层位 id 沿用 P00–P80，**层名与模块挂载是技术文档特化**（九层默认模块 = M90，输出层 = 核心 M80）；`structure.type: techdoc` 是 01 §2 值域扩展的首个归档先例。
- **怎么用**：本管线是「扩展新领域三步」的闭环样例；新领域照此复制 P00 → 改 id/name/层名/挂载/flow/tags → 02 登记，引擎不改（I5）。
- **怎么验**：挂载与执行顺序的真相源 = `02_联动注册表.md` §7.1（P90 挂载）/ §7.2（10 步执行顺序），本文件与它逐层一致；结构声明由 `protocol/schema/pipeline.schema.json` 约束（check28）；抽象执行由 `nf conformance` 的 pipeline-dryrun 契约跑。
- **边界**：M00 数据槽 / M50 主循环 / M80 输出门是唯一核心门，P90 与官方核心实例共用、不改动（I2）。

```yaml
Pipeline:
  id: P90
  name: 技术文档生成管线
  structure:
    type: techdoc
    flow:
      - from: P00
        to: P10
      - from: P10
        to: P20
      - from: P20
        to: P30
      - from: P30
        to: P40
      - from: P40
        to: P50
      - from: P50
        to: P60
      - from: P60
        to: P70
      - from: P70
        to: P80
      - from: P80
        to: P00
        condition: =data_bus.round.phase == "roll"
  layers:
    - id: P00
      name: 文档装载
      description: 初始化数据槽并解析用户意图 → 章节骨架装载；M90 在此判定文档类型并装配模板
      optional: false
      default_modules: [M90]
      allowed_modules: [M90]
    - id: P10
      name: 语境推进
      description: 上下文/版本/相关文档状态推进；本线默认无外部推进模块（M90 自持）
      optional: false
      default_modules: [M90]
      allowed_modules: [M90]
    - id: P20
      name: 章节状态
      description: DocState 章节/术语/引用增量结算（标题层级、首现术语登记）
      optional: false
      default_modules: [M90]
      allowed_modules: [M90]
    - id: P30
      name: 片段生产
      description: 按章节骨架逐节生成内容片段候选集（概述/操作步骤/示例…）
      optional: false
      default_modules: [M90]
      allowed_modules: [M90]
    - id: P40
      name: 结构决策
      description: 依据 DocState 与候选片段裁决章节取舍/模板选择/分节策略
      optional: false
      default_modules: [M90]
      allowed_modules: [M90]
    - id: P50
      name: 章节装配
      description: 把决策结果装配为可输出章节（正文/表格/代码块引用组装）
      optional: false
      default_modules: [M90]
      allowed_modules: [M90]
    - id: P60
      name: 一致性
      description: 跨章一致性维护：术语同词同义、引用闭合、修订记录追加（optional）
      optional: true
      default_modules: [M90]
      allowed_modules: [M90]
    - id: P70
      name: 规范素材
      description: 领域规范库为输出层提供模板与校验规则（TECH_TEMPLATES / TECH_RULES，optional）
      optional: true
      default_modules: [M90]
      allowed_modules: [M90]
    - id: P80
      name: 文档输出
      description: 按规范模板渲染最终文档；经核心 M80 输出质检门后落盘
      optional: false
      default_modules: [M80]
      allowed_modules: [M80]
  dependencies:
    - from: P20
      to: P30
      reason: 章节状态是片段生产的输入画像
    - from: P30
      to: P40
      reason: 候选片段是结构决策的输入
    - from: P40
      to: P50
      reason: 决策结果驱动章节装配
    - from: P50
      to: P60
      reason: 装配产物回写一致性校验
  tags: [结构化装配, 领域示例, 文档工厂实证, 线性]
```

## 全局挂载（核心固定，I2）
- M50 调度器：调度各层执行与回卷（读取 02 §7 登记，禁止硬编码顺序）。
- M00 数据槽总线：数据槽承载（DocState 承载于其槽位）。
## 运行规则

- 本管线 = P00 骨架按 01 §2 派生：层名/挂载为结构化装配特化；新增领域只需再复制 P00 → 改 id/name/层名/挂载/flow/tags → 02 登记，引擎不改。
- 素材层键：TECH_TEMPLATES（章节骨架）/ TECH_RULES（规范校验）——经 asset_get/asset_query 访问（I4）。
- 输出层唯一出口：M80（质检门），与其它装配线共用核心门，语义一致——gate_action 声明式流水线（pass: [direct] / warn: [self_correct, log_revision] / fail: [rewrite, retry_limit: 3, fallback: minimal]）与决策记录格式以 M80 §3 为唯一真相源，本管线只引用不另立（I5 引擎不改）。
- **同源判据**：本管线九层的层名 / default / available 必须与 `02_联动注册表.md` §7.1 P90 挂载逐层一致（02 §7 为该实例挂载与执行顺序的真相源，I5）；执行顺序 10 步见 02 §7.2。
- **机检**：`bash verify.sh`（管线声明过 IDL schema）+ `nf conformance` 的 pipeline-dryrun 契约（techdoc 结构）。
